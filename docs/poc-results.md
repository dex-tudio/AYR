- Core: **50개 통과, 실패 0개**. 저장소: **15개 통과**. 복구: **12개 통과**. 공통 금액 입력·표시: **3개 통과**. 모든 iOS Swift 파일 문법 검사 통과.
- 온보딩 완료 전에 실제 결제로 테스트하도록 읽힐 수 있던 안내를 수정했습니다. 실제 결제 확인 전에 `시작하기`로 설정을 완료하도록 안내하고, 완료 전 결제 거부 사유도 앱에 남깁니다.
- 온보딩을 며칠에 걸쳐 진행하면 완료 전 날짜가 0원으로 포함되던 결함을 수정하고 회귀 검사를 추가했습니다.
- 독립 검토에서 반복 날짜 역행 시 온보딩 이전의 가상 0원이 생기는 문제, 보관 날짜에서 설정을 바꾼 뒤 건너뛴 새 날짜·월의 기준이 과거 값으로 채워지는 문제를 재현했습니다. 각각 수정 전 실패하는 회귀 검사 후 수정하고 재검증했습니다.
- 새 필드는 이전 저장에서 생략돼도 읽을 수 있습니다. 새 저장은 버전 2를 써 이전 앱의 잘못된 합산을 차단하고, 다른 버전은 원본을 지우지 않고 업데이트를 안내합니다. 기존 검사에서 미래 버전으로 쓰던 `2`는 지원 버전이 되어 `99`로 바꿨습니다.
- 당일 보정 저장소 검사에서 수신 시각의 원본 소수 초와 ISO8601 저장 시각(초 단위)을 비교하던 검사를, 저장된 시각과 변경 후 시각을 비교하도록 교정했습니다. 저장 형식과 금액 기대값은 바꾸지 않았습니다.
- 독립 검토에서 자정 이후 추가 폼을 닫아야만 재시도할 수 있던 문제를 찾아, 입력 금액을 유지한 채 사용자가 오늘 날짜를 다시 확인하고 추가할 수 있게 수정했습니다. API 경계의 거부·재시도는 저장소 검사로 확인했으며 실제 화면 조작은 미검증입니다.
- 이전 POC 리팩토링: 날짜 이월·빈 날짜 채우기·지난달 비교를 private 메서드로 분리하고, 금액 표시·신분/기준 입력을 공통화했습니다. 앱의 중복 재조회와 무의미한 저장 옵션을 제거하고 월별 화면의 강제 해제를 없앴습니다. 이번 정책 반영에서는 이후 필드를 추가하되 이전 기록의 읽기 호환성을 유지했습니다.
- 발견·수정: 읽기만 하는 위젯에서도 날짜 변경·보관 기간 정리를 파일에 반영하도록 수정하고 회귀 검사 추가. 저장 실패 검사 초기 버전은 상태 변경이 없어 쓰기가 생기지 않았으므로 실제 변경 후 쓰기를 실패시키도록 검사 자체를 교정했습니다.
- 독립 소스 검토에서 위젯의 미연결 URL을 제거하고 기본 앱 열기를 사용하도록 수정했습니다.
- 기준 커밋 `f00c142`의 macOS CI 빌드는 통과했습니다. 이번 변경은 아직 원격 CI에서 실행하지 않았습니다. Linux 검사는 SwiftUI·ActivityKit의 Apple SDK 타입 검사를 대신하지 않습니다.
- 다음 검증: Apple SDK 빌드 → TestFlight 준비·설치 → 온보딩·가짜 본문 Intent·월별·잠금화면 → 다음 평소 KB 결제에서 실제 수집. 신규 결제는 요구하지 않습니다.
- 알려진 제한: 중복 알림을 구분하지 못함, KB 취소 형식 미확인. 복원된 기존 합계는 보호하며 새 항목만 관리합니다. 이전 형식에서 보관하지 않았던 과거 월 예산은 추정값이고, 보관한 손상 원본의 복원·삭제 화면은 없습니다. iOS 파일 보호·복구 확인창·Live Activity 종료와 동시 갱신은 기기 미검증입니다.
