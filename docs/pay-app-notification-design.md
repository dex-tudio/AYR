# 카카오페이·Npay 앱 알림 공통 템플릿 설계

작성일: 2026-11-08. 상태: **설계 제안 기록 — 미구현, 실기기 입력 형식 미검증**.

대화에서 검토한 방향을 보존한다. 이 문서는 현재 지원 범위나 [MVP 확정 명세](mvp-spec.md)를 변경하지 않으며, Intent 인터페이스 확장과 중복 수집 정책은 구현 전에 확정한다.

## 목적과 현재 상태

카카오페이·네이버페이의 결제 알림을 단축어 자동화로 받아, 기존 `AYR 결제 처리`에서 합계·문구·잠금화면 표시를 갱신하는 방향이다. 수단마다 같은 템플릿을 사용하고, 앱과 입력 수단만 다르게 지정한다.

- 실제 문자 자동 수집은 사용자 확인으로 성공했다. 앱 알림 수집 성공을 의미하지는 않는다.
- 현재 앱 해석기는 KB국민 체크카드 문자 승인만 지원한다.
- 현재 Intent는 `text: String` 하나를 받고 화면에 `문자 본문`으로 표시한다. 입력 수단 매개변수는 없다.
- 연결 안내·연결 확인은 선택한 지원 SMS 수단을 공통 화면에서 표시하도록 구현돼 있다. 앱 알림 경로 안내는 아직 없다.

## 새로 확인한 근거

- [Apple iOS 27 업데이트 안내](https://support.apple.com/en-asia/149045)에 알림 수신 자동화가 추가됐다고 명시돼 있다. [이벤트 트리거 문서](https://support.apple.com/en-tm/guide/shortcuts/apd932ff833f/ios)는 대상 앱과 Message·Subtitle·Title 필터를 설명한다. 공식 검색 색인에서 확인했으며 직접 페이지 조회에는 429 오류가 있었다. **필터 항목의 존재가 단축어 입력에서 동일한 속성을 읽을 수 있다는 증거는 아니다.**
- 카카오페이 결제 완료 알림의 [개발자 공개 예시](https://ksyy.tistory.com/267)가 있다. 테스트 결제 화면이며, 현재 카카오페이 앱푸시의 전달 본문을 확정하는 자료는 아니다.
- 네이버페이 해외 QR 결제·머니 충전의 [공개 화면 예시](https://ameblo.jp/bonjour-aloha-annyon/entry-12784289274.html)를 검색 이미지에서 찾았다. 현재 국내 결제·취소의 고정 템플릿으로 사용하지 않는다.
- [Npay 공식 도움말](https://help.pay.naver.com/faq/content.help?faqId=16045)은 네이버 앱과 Npay 앱을 함께 쓰면 중복 방지를 위해 Npay 앱으로만 푸시를 보내는 경우를 설명한다. 실제 알림 발신 앱을 확인해야 한다.

근거 확인일은 2026-11-08이다. 과거 알림톡 화면, 앱 내부 알림 목록, 잠금화면 푸시, 단축어에 전달된 값은 각각 구분한다. 추가 조사 전의 상태는 [결제 알림 조사](payment-notification-research.md)에 보존돼 있다.

## 공통 자동화 템플릿 제안

자동화는 두 개로 나누고 같은 처리 Intent를 호출한다. 카카오톡의 모든 메시지나 네이버 앱 전체 알림을 결제로 간주하지 않는다.

| 설정 | 카카오페이 자동화 | 네이버페이 자동화 |
| --- | --- | --- |
| OS 조건 | iOS 27 이상 | iOS 27 이상 |
| 트리거 | 알림 수신 | 알림 수신 |
| 대상 앱 후보 | 카카오페이 | Npay |
| 입력 수단 | 카카오페이 앱 알림 | 네이버페이 앱 알림 |
| 호출 동작 | 기존 `AYR 결제 처리` | 기존 `AYR 결제 처리` |
| 전달 내용 후보 | 읽을 수 있는 제목·부제·본문 | 읽을 수 있는 제목·부제·본문 |

실기기에서는 먼저 앱만 지정해 연결 가능성을 확인한다. 실제 전달값을 확인한 뒤 고정 문구로 필터를 좁힌다. 초기부터 `결제 완료`만 조건으로 걸어 취소·자동결제를 놓치지 않도록 한다. 묻지 않고 실행·잠금 상태 실행·알림 미리보기 설정의 영향도 별도로 확인한다.

제목·부제·본문 중 어떤 속성이 실제 입력으로 제공되는지, 비어 있거나 잘리는지 확인하기 전에는 조합 순서·구분자·필터 문자열을 확정하지 않는다. 단축어는 원문을 전달하고 금액 추출·승인·취소 판정은 앱에서 처리한다.

## 필요한 앱 변경 제안과 호환성

| 영역 | 제안 |
| --- | --- |
| Intent 입력 | 기존 `text`를 유지하고 선택적인 입력 수단을 추가한다. 생략하면 기존 문자 처리로 동작하게 한다. 구체적인 매개변수 타입·식별자는 미확정 |
| 내용 전달 | 앱 이름이 알림 본문에 없어도 출처를 구별하도록 수단을 별도로 전달한다. 실제 제공 속성을 확인한 뒤 제목·본문의 전달 방식을 정한다 |
| 해석기 | 카카오페이·Npay를 구분해 확인한 형식만 해석한다. 충전·송금·적립·결제 요청은 소비 승인에서 제외한다 |
| 연결 안내 | 문자와 앱 알림의 설정 순서를 구분하고, 지원 OS와 대상 앱을 안내한다 |
| 지원 표시 | 입력 형식·해석기·실기기 수신을 검증하기 전까지 준비 중으로 유지한다 |

기존 KB 자동화를 다시 만들도록 요구하지 않는다. Intent 이름은 하나로 유지하며 새 동작을 수단별로 추가하지 않는다. 원문·상점명은 저장하거나 로그로 남기지 않고, 검증 입력은 개인정보와 금액을 가짜 값으로 바꾼다. 서버나 외부 AI로 본문을 보내지 않는다.

## 구현 전에 해결할 사항과 검증

| 확인할 사항 | 완료 근거 |
| --- | --- |
| 알림 발신 앱·입력 속성 | 각 앱의 평소 결제에서 실제 트리거와 전달값의 구조 확인. 원문은 Git·채팅·로그에 기록하지 않음 |
| 제목/본문 분리·빈 값·잘림 | 사용 가능한 입력 조합을 확정하고 불완전한 입력은 합산하지 않는 검사 |
| 승인·자동결제·취소·충전·송금·적립 | 확보한 형식마다 비식별 회귀 입력을 만들고 금액 선택·제외 동작 검증. 미확인 형식을 임의 구현하지 않음 |
| 카드 문자와 페이 알림 중복 | 같은 결제가 두 경로로 들어올 때의 수집 경로 선택 또는 중복 처리 정책 확정 |
| 포인트+카드/머니 복합 결제 | 알림 금액이 총액인지 실제 차감액인지 확인한 뒤 집계 기준 확정 |
| 기존 문자 호환성 | 입력 수단을 생략한 기존 KB 자동화의 수신·합산 유지 |
| 기기 동작 | 잠금·미리보기 제한·앱 종료·연속 알림·지연·권한 거부/복구에서 수신과 위젯·Live Activity 결과 확인 |

공개 예시는 해석기 검토의 출발점이며 최신 전달 형식의 확정 근거는 아니다. 카드 문자와 페이 알림을 동시에 합산하는 중복 제거 기능은 현재 없다. 연결 카드 자동화를 전부 끄면 직접 카드 결제가 누락될 수 있으므로, 이를 일괄 해결책으로 안내하지 않는다.

다음 실행 단위는 **카카오페이 앱 알림의 입력 구조·잠금 상태 전달 확인**이다. 그 결과로 공통 입력 계약을 확정한 뒤 카카오페이 해석기·검사·안내를 함께 구현하고, Npay에도 같은 틀을 적용한다. 확인만을 위한 신규 결제는 요구하지 않는다.
