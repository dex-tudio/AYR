# MVP 확정 명세

상태: PWA + 서버 + 금융 API 방향으로 전환 확정. 실제 데이터 제공사·이용 자격·인증 방식은 검증 전입니다.

## 목표와 범위

- 실제 결제를 수동 입력 없이 수집하고 오늘 합계와 신분별 문구를 갱신합니다.
- Android와 iPhone의 모바일 웹/PWA를 대상으로 합니다. 최초 희망 수집 대상인 토스페이 온라인 결제와 토스뱅크 체크카드는 API 지원 여부를 각각 검증합니다.
- 사용자 금융정보 연결·동의 → 서버의 금융 API 거래 수집 → 오늘 합계·문구 계산 → PWA 화면·푸시 갱신을 구현 방향으로 확정했습니다.
- 단축어, 금융 앱 알림 읽기, Flutter, 네이티브 Live Activity는 현재 개발 경로에서 제외합니다. 기존 iPhone 단축어 POC 문서는 이전 조사 기록으로만 보관합니다.
- 개발·검증은 무료 우선입니다. 유료 운영·사업자 계약도 검토할 수 있지만, 유료 신청·계약·결제·배포는 별도 승인 없이 진행하지 않습니다.
- 서버와 금융정보 연동이 범위에 포함됩니다. 사용자별 인증·접근 제어가 필요하며 구체적인 로그인 방식과 호스팅·DB·프레임워크는 제공사 계약 확인 후 확정합니다.
- 사용자의 수동 지출 입력, 다른 금융사로의 임의 전환, 샘플 데이터를 실연동으로 표시하는 것은 포함하지 않습니다.
- 첫 단위는 실제 데이터 API의 지원 범위·가입 자격·동의 및 인증 흐름 확인입니다. API가 존재한다는 사실만으로 이 서비스가 이용 가능하다고 판단하지 않습니다.

## 금액과 문구

최초 실행 시 신분을 선택합니다. 신분 변경 시 금액은 유지하고 문구만 즉시 재계산합니다. 금액 기준과 문구의 사용자 편집 기능은 없습니다.

| 신분 | 하루 기준 금액 |
| --- | ---: |
| 학생 | 20,000원 |
| 취준생 | 30,000원 |
| 직장인 | 50,000원 |

| 오늘 합계 / 하루 기준 금액 | 표시 문구 |
| --- | --- |
| 50% 미만 | 아직 여유 있어요 |
| 50% 이상, 100% 미만 | 슬슬 조절해볼까요? |
| 100% 이상 | 님 부자임? |

금액은 원 단위 정수로 계산합니다. 표시 예: `오늘 12,000원 · 슬슬 조절해볼까요?`(학생).

## 집계 규칙

| 상황 | 확정 동작 |
| --- | --- |
| 정상 승인 | 확인된 실제 결제 금액을 합산합니다. 요청·인증·광고는 제외합니다. |
| 날짜 변경 | 휴대폰 현지 날짜로 오늘 합계를 다시 계산합니다. 과거 거래를 즉시 삭제하지 않습니다. |
| 자정 갱신 지연 | OS 지연을 허용합니다. 다음 수신·앱 실행·예약 실행 시에는 당일 기준으로 표시합니다. |
| 늦게 수집된 거래 | 신뢰할 수 있는 결제일시가 있으면 그 날짜, 없으면 수집일을 사용하고 날짜 추정 상태를 기록합니다. |
| 전체·부분 취소 | 원거래의 결제일에서 차감합니다. 전날 결제 취소로 오늘 합계가 줄어들지 않습니다. |
| 원거래 미확인 | 임의 차감하지 않고 부분 집계 상태로 안내합니다. |
| 같은 거래 재조회 | 한 번만 반영합니다. 제공사의 거래 식별자·상태를 기준으로 판단하며 금액만으로 중복을 판별하지 않습니다. |
| 같은 금액의 별도 결제 | 각각 반영합니다. |
| 금액·거래 종류 불명확 | 임의 합산하지 않고 해석 실패 상태로 안내합니다. |
| 알려진 수집 중단·누락 | 확인된 금액과 부분 집계 상태를 함께 표시합니다. 과거 내역 자동 복구를 보장하지 않습니다. |
| 외화 | 신뢰할 수 있는 원화 승인 금액이 있으면 반영합니다. 외화 금액만 있으면 제외하고 안내합니다. |

지원·연결된 기관과 수집 범위 안의 거래만 집계합니다. 조회하지 않은 기간과 다른 계좌·결제수단까지 전체 지출로 보장하지 않습니다. 계좌 출금·송금·충전·카드대금 납부를 전부 소비로 처리하지 않으며, 계좌와 카드에서 같은 소비를 중복 합산하지 않습니다.

## 표시와 권한

- PWA 화면에서 오늘 합계·문구·마지막 동기화 시각·수집 범위를 표시합니다. 미연결·미조회 상태를 정상적인 0원으로 표시하지 않습니다.
- 서버가 새 거래를 확인하면 집계 후 웹 푸시를 보냅니다. iPhone은 홈 화면 추가와 알림 허용이 필요하며 지원 OS·브라우저 범위를 실제로 검증합니다.
- 일반 웹 푸시를 사용합니다. 하루 종일 고정되는 배너·Live Activity와 동일한 표시를 보장하지 않습니다.
- 금융 앱의 알림을 켜거나 단축어를 편집할 필요가 없는 연결 흐름을 목표로 합니다. 금융정보 연결 동의와 제공사의 인증은 필요합니다.
- 금융 조회 동의와 웹 푸시 권한을 구분합니다. 푸시 거부·구독 만료를 거래 수집 실패로 간주하지 않습니다.
- 동의 만료·철회·조회 실패 시 상태와 복구 방법을 표시합니다. 실패를 0원으로 덮어쓰지 않습니다.
- 사용자가 허용한 목표 갱신 지연은 결제 후 최대 15분입니다. 제공사의 웹훅·조회 주기·요금·제한을 검증해야 하며, 이 목표를 실제로 보장할 수 있는지는 아직 미확정입니다.

## 저장과 개인정보

- 최소 거래 정보는 서버에서 사용자별로 최근 90일 보관하는 방향으로 변경합니다. 기간 밖 거래 취소 등 원거래를 확인할 수 없는 상황은 부분 집계 상태로 표시합니다.
- 금융 데이터 제공사·앱 서버·웹 푸시 서비스 사이의 데이터 흐름과 보유 기간을 연결 전에 안내해야 합니다. 실제 제공사의 계약·동의 범위에 맞게 확정합니다.
- 개인별 접근 제어와 서버 자격증명 보관이 필수입니다. 거래 원문·금융 인증정보·토큰을 Git·채팅·브라우저 저장소·로그에 노출하지 않습니다.
- 금융기관 비밀번호·인증서를 직접 수집하는 방식을 임의로 도입하지 않습니다. 제공사의 정식 연결·인증 경로를 확인합니다.
- 연결 해제·탈퇴·동의 철회 시 조회 중단과 데이터 삭제 범위, 백업·복구 정책은 실제 제공사와 인증 설계에 맞춰 확정해야 합니다.

## 실행 단위와 완료 기준

1. **제공사 선택과 실데이터 접근 검증:** [금융 API 검토 기록](financial-api-review.md)의 필수 질문을 해결하고, 지원 상품·인증 흐름·스키마·취소·갱신 주기를 확인합니다. 샌드박스 응답과 실제 거래를 구분합니다.
2. **사용자 연결·동의 → 서버 수집 → 오늘 합계 화면:** 사용자 격리, 거래 식별·중복·취소·날짜 집계를 연결해 검증합니다.
3. **합계 → 신분별 문구 → PWA 푸시:** 경계값·신분 변경·홈 화면 설치·알림 권한·실제 푸시 수신을 검증합니다.
4. **실패·복구 통합 검증:** API 지연·제한·동의 만료·철회·재조회·일부 조회 실패·날짜 변경·저장 실패·푸시 만료 시 일관성을 확인합니다.

각 단위의 검증이 통과한 뒤 다음 단위로 진행합니다. 커밋·푸시·배포는 별도 요청 없이는 하지 않습니다.

## 아직 검증 전인 기술 항목

- 실제 제공사와 개인 개발·운영 이용 자격, 테스트 무료 범위와 운영 가격.
- 토스페이·토스뱅크 체크카드 소비·전체/부분 취소의 제공 범위와 상호 연결 정보.
- 사용자 동의·인증·연결 해제·재인증 경로와 관련 계약상 이용 조건.
- 거래 식별자·결제일·취소 연결·통화·증분 조회·정정 정보와 조회 제한.
- 거래 반영 지연, 서버 갱신 방식, 재시도와 푸시 전달 시점.
- 데이터 계약 확정 후 선택할 웹 프레임워크·인증·DB·호스팅 구성 및 검증 환경.

입력 정보가 부족하면 수집 가능한 것처럼 구현하지 않고 실패한 조건을 보고합니다. 다른 금융사·유료 API·배포로 범위를 자동 확장하지 않습니다.
