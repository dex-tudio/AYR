# MVP 확정 명세

상태: iOS 네이티브 앱 POC 코드 구현·QA 정책 반영(2026-11-05). 본인 사용으로 검증하고 지인·외부 배포를 목표로 합니다. `f00c142`의 앱·위젯 시뮬레이터 빌드는 CI에서 통과했고, 이후 QA 정책 변경분의 Apple SDK 빌드와 실기기 동작은 미검증입니다.

## 목표와 범위

- 결제 문자·알림을 수동 입력 없이 반영해 오늘 합계와 문구를 잠금화면에 보여줍니다.
- 당일 지출은 앱에서 금액을 추가하거나 삭제해 보정할 수 있습니다(2026-11-04 추가). 자동 수집을 대체하는 흐름으로 보지 않습니다.
- 수집: 결제 알림·문자 → 단축어 자동화 → 고정 App Intent `AYR 결제 처리`. iOS는 앱이 알림·문자를 읽거나 자동화를 대신 만들 수 없어 사용자가 자동화를 만들고, 앱은 맞춤 설정 안내와 수신 테스트를 제공합니다.
- 계산·저장: 앱이 기기 안(App Group)에 저장합니다. 서버·계정·외부 전송은 없습니다.
- 표시: 잠금화면 위젯(항상, 자정에 0원 항목)과 Live Activity(결제 처리·앱 실행 시 시작·갱신, 활성 최대 8시간·잠금화면 최대 12시간이라 하루 종일 고정은 불가), 앱 화면.
- 지원 수단: KB국민 체크카드 문자. 토스페이·토스뱅크 체크카드 알림과 그 외는 형식 확인 전까지 '준비 중'. 결제 수단 하나당 수집 경로는 하나만 써서 중복 합산을 막습니다. Android는 범위 밖입니다.
- 빌드: Mac 없이 GitHub Actions macOS 러너에서 빌드합니다. 최소 iOS 17. 2026-11-04 최신 결정: 실제 문자 검증·Windows 사이드로딩 검증을 구현의 선행 조건으로 두지 않고, 온보딩·월별·잠금화면 표시를 포함한 POC부터 구현한 뒤 TestFlight로 테스트합니다. 가입·서명·배포는 아직 실행하지 않았습니다.
- 이전 PWA·서버·금융 API·앱인토스 조사는 [금융 API 검토 기록](financial-api-review.md)에 보관합니다.

## 금액과 문구

## 온보딩

1. 신분 선택 → 기준 금액 기본값 표시, 직접 수정 가능(원 단위 양의 정수).
2. 결제 수단 선택(복수). 미지원 수단은 '준비 중', 선택 불가.
3. 표시 설정: Live Activity 허용, 잠금화면 위젯 추가 안내.
4. 수단별 자동화 설정 안내(예: KB 문자 → 메시지 트리거, `KB국민체크` 포함 필터, 즉시 실행, 동작 `AYR 결제 처리`).
5. 수신 테스트: 테스트 문구(`KB국민체크 AYR테스트`)를 자기 자신에게 보내 자동화가 앱을 호출하는지 확인. 테스트는 합산하지 않습니다. 자기 자신에게 보낸 메시지에 트리거가 반응하는지는 미확인이며, 안 되면 먼저 `시작하기`로 온보딩을 완료한 뒤 다음 평소 결제로 확인합니다. 완료 전 실제 결제 문자는 반영하지 않습니다.

설정 화면에서 신분·기준 금액·월 예산·결제 수단·수신 테스트를 다시 할 수 있습니다. 신분이나 기준 금액을 바꾸면 오늘 금액은 유지하고 문구만 다시 계산합니다.

2026-11-05 결정(2B): 신분을 바꾸면 직접 입력했던 하루 기준 금액도 새 신분의 기본값으로 바꿉니다. 이미 합계로 보관했다가 시간대 변경으로 다시 열린 날짜는 그 날짜의 원래 기준을 유지합니다.

| 신분 | 기준 금액 기본값 |
| --- | ---: |
| 학생 | 20,000원 |
| 취준생 | 30,000원 |
| 직장인 | 50,000원 |

| 오늘 합계 / 기준 금액 | 표시 문구 |
| --- | --- |
| 50% 미만 | 아직 여유 있어요 |
| 50% 이상, 100% 미만 | 슬슬 조절해볼까요? |
| 100% 이상 | 님 부자임? |

금액은 원 단위 정수입니다. 표시 예: `오늘 12,000원 · 슬슬 조절해볼까요?`(학생).

## 집계 규칙

| 상황 | 동작 |
| --- | --- |
| 승인 알림 | 승인 금액을 오늘 합계에 더합니다. 결제 요청·인증·광고·송금·충전 알림은 제외합니다. |
| 날짜 변경 | 기기 현지 시간대의 양력 날짜(`yyyy-MM-dd`)가 바뀌면 다음 알림·앱 실행·위젯 갱신 때 0원부터 다시 집계합니다. 기기의 대체 달력 설정과 무관하게 양력을 씁니다. 자정 정각 갱신은 보장하지 않습니다. |
| 취소 알림 | 오늘 승인 중 같은 금액이 있으면 그 승인 1건을 뺍니다. 없으면(전날 결제 취소, 부분 취소) 차감하지 않고 무시합니다. 알림에는 원거래 정보가 없어 생긴 한계입니다. |
| 같은 금액의 별도 결제 | 각각 반영합니다. |
| 같은 알림 중복 수신 | 알림에 거래 ID가 없어 구분하지 못하고 두 번 합산될 수 있습니다. |
| 금액·종류 해석 실패 | 합산하지 않습니다. |
| 0원 이하 금액 | 거부합니다. |
| 외화 | 원화 금액이 없으면 합산하지 않습니다. |


해석 규칙은 실제 형식을 확인한 것만 둡니다.

| 원천 | 확인한 형식 | 규칙 |
| --- | --- | --- |
| KB국민 체크카드 문자 | 승인: `KB국민체크(끝4자리)` / 이름 / `MM/dd HH:mm` / `5,100원` / `가게이름 사용` | `KB국민체크` 줄, 마지막 줄 `… 사용`, 금액만 있는 줄 정확히 1개일 때 승인 |
| KB국민 체크카드 취소 | 미확인 | 합산·차감하지 않음 |
| 토스 알림 | 미확인 | 미구현 |

2026-11-05 결정(4A): 마지막 자동화 호출 시각과 처리 결과(반영·테스트·해석 불가·금액 범위 초과·설정 미완료)를 기기 안에 저장하고 오늘 화면·수신 테스트 화면에 표시합니다. 실패해도 마지막 정상 합계·수신 시각은 유지합니다. 원문·금액·가게 이름을 실패 사유에 넣지 않습니다. 저장 공간에 접근할 수 없으면 호출 상태도 남길 수 없습니다.

## 당일 지출 추가·삭제

2026-11-04 사용자 결정: 자동·수동 지출 모두 삭제 가능하며, 이후 들어오는 문자는 별도로 합산합니다.

| 항목 | 동작 |
| --- | --- |
| 진입 | 오늘 화면 → 오늘 지출 추가·삭제. 당일 금액 목록과 합계를 봅니다. |
| 추가 | 원 단위 양의 정수 금액만 입력합니다. 합계·문구·월별 기록·위젯·Live Activity에 반영합니다. |
| 삭제 | 자동 수집·수동 추가 여부와 무관하게 선택한 항목 1건을 확인 후 삭제합니다. 같은 금액이 여러 건이어도 선택한 한 건만 삭제합니다. 마지막 항목 삭제 시 합계는 0원입니다. |
| 범위 | 현재 기기 시간대의 양력 날짜만 수정합니다. 과거 날짜 수정·하루 전체 초기화·항목 금액 편집은 제공하지 않습니다. |
| 날짜·목록 변경 | 입력 후 날짜가 바뀌었거나 삭제 확인 중 목록이 바뀌면 반영하지 않습니다. 입력 금액은 유지하고 사용자가 오늘 날짜를 다시 확인한 후 추가할 수 있습니다. 삭제는 최신 목록에서 다시 선택합니다. |
| 실패 | 저장에 실패하면 입력을 유지하고 재시도할 수 있습니다. 실패한 변경으로 기존 파일을 덮어쓰지 않습니다. |
| 뒤늦은·중복 수신 | 수동으로 추가했거나 삭제한 결제와 같아 보여도 새 문자는 별도로 합산합니다. 거래 ID가 없어 자동으로 중복을 판정하지 않고, 사용자가 당일 목록에서 삭제합니다. |
| 기록 | 기존 당일 금액 목록만 사용하며 원문·상점명·수동/자동 출처는 추가로 저장하지 않습니다. 수동 조작을 자동화 수신 성공으로 표시하지 않습니다. |

2026-11-05 결정(5A): 시간대·날짜 변경으로 이미 합계로 접힌 날짜가 다시 오늘이 되면 기존 금액은 `이전 합계`로 보호합니다. 거래 한 건처럼 복원하지 않으며 삭제·취소 대조 대상에서 제외합니다. 그 뒤 새로 들어온 자동·수동 금액만 개별 삭제할 수 있고, 전체 합계에는 이전 합계와 새 금액을 모두 포함합니다. 원래 날짜의 기준 금액도 유지합니다.

이전 버전이 이미 합계 한 건으로 복원해 저장한 당일 목록은 실제 결제 한 건인지 구분할 수 없어 그대로 읽습니다. 원래 개별 구성을 복원하지 않으며 다음 날짜 이월부터 새 보호 규칙을 적용합니다.

## 월별 관리

앱 화면(잠금화면 아님)에서 월 단위로 봅니다. 월 경계는 기기 현지 날짜 기준입니다.

| 항목 | 동작 |
| --- | --- |
| 월 합계 | 이번 달 날짜별 합계의 합. 월을 앞뒤로 넘겨 지난 기록도 봅니다. |
| 달력 | 날짜 칸에 그날 합계와 그날 문구 구간 색(여유 / 슬슬 / 님 부자임?)을 표시합니다. |
| 문구별 일수 | 그 달의 여유·슬슬·님 부자임? 일수. 각 날짜는 **그날의 기준 금액**으로 판정합니다(나중에 기준 금액을 바꿔도 과거 판정은 그대로). |
| 지난달 비교 | 이번 달 1일~오늘까지 합계와 지난달 1일~같은 날짜까지 합계의 차이. 지난달에 같은 날짜가 없으면(예: 31일) 지난달 말일까지로 비교합니다. |
| 월 예산 | 기본값은 하루 기준 금액 × 그 달 일수이고 직접 수정할 수 있습니다(원 단위 양의 정수). 변경은 현재 달부터 반영하며 지난달 예산은 보존합니다(2026-11-05 결정 1A). 직접 입력한 월 예산은 이후 달에도 기본으로 사용합니다. 남은 금액 = 월 예산 − 월 합계, 넘으면 `N원 초과`로 표시합니다. |

**기록 규칙**
- 날짜별로 `합계`와 `그날의 기준 금액`, 월별로 `예산`을 저장합니다. 결제 건별 내역·가게 이름·문자 원문은 저장하지 않습니다. 당일 금액 목록은 오늘 것만 유지하고, 날짜가 바뀌면 합계로 접습니다.
- 첫 기록일(온보딩 완료 당시 현지 날짜) 이후 결제가 없던 날은 0원으로 보고, 그 이전 날짜는 `기록 없음`으로 표시합니다. 단, 시간대 변경 후 더 이른 현지 날짜에 실제 기록을 추가한 경우 그 금액은 표시하며, 그 전후의 가상 0원 기록은 만들지 않습니다. 자동화가 꺼져 있던 날도 0원으로 보일 수 있으며 앱은 이를 구분하지 못합니다.
- 전날 결제를 오늘 취소한 경우 과거 날짜를 고치지 않습니다(알림에 원거래 정보가 없음).
- 이번 달 포함 최근 12개월을 보관하고, 그보다 오래된 날짜 기록은 자동 삭제합니다.
- 월 예산도 같은 기간 보관합니다. 이전 버전에는 월별 예산 이력이 없어 당시 직접 입력값을 복원할 수 없습니다. 기존 기록은 저장된 최신 월 예산 또는 날짜별 기준으로 초기 예산을 추정해 보존합니다.
- 날짜별 기록과 월 예산은 POC부터 저장하고 월별 화면에서 조회합니다.

| 7 | 실제 KB 문자 자동화 | 다음 평소 결제에서 잠금 상태의 즉시 실행·실제 합계 반영 | 미실행 |

- 온보딩 수신 테스트는 나중으로 미루고 완료할 수 있습니다. 수신 미확인을 실제 수집 성공으로 표시하지 않습니다.
- 가짜 본문은 단축어에서 Intent를 확인하는 검증 입력입니다. 앱의 당일 수동 보정은 실제 자동 수집 검증을 대신하지 않습니다.
- 실제 문자가 전달되지 않으면 수집 POC는 실패로 기록하고 수집 경로를 재검토합니다.

### 설치·계정과 검증 대기

- Windows 사이드로딩 검증은 더 이상 구현의 선행 작업이 아닙니다. TestFlight로 테스트하는 최신 요청을 따릅니다. 유료 가입·결제·자격 증명 설정·업로드는 사용자가 직접 진행하거나 해당 작업을 별도 승인합니다.
- 프로젝트 식별자는 임시 `dev.ayr.app`, `dev.ayr.app.widgets`, `group.dev.ayr.shared`입니다. TestFlight 전에 본인 소유 값으로 맞추고 앱 아이콘·서명·배포 설정도 준비해야 합니다.
- 메시지 트리거 실기기 테스트는 미실행입니다. 검증만을 위해 새로 결제하지 않고 다음 평소 KB 체크카드 결제에서 확인합니다. 가짜 문자는 실제 KB 발신 검증을 대체하지 않습니다. 문자 원문·금액·상점명은 기록하거나 공유하지 않습니다.
- 실행 결과·실패와 복구 검사는 [POC 검증 기록](poc-results.md)을 봅니다.
