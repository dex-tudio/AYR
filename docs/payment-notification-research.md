# 결제 알림 템플릿·단축어 연결 조사

조사일: **2026-11-08**. 공개 웹·공식 서비스 안내·공개 개발자 예시를 조사했다. 현재 공개 페이지의 조회일은 템플릿의 적용일과 다르다. 아래에서 날짜가 없는 서비스 안내는 게시일 미표시이며, 요금·채널은 신청 직전에 재확인한다.

후속 조사·설계: [카카오페이·Npay 앱 알림 공통 템플릿](pay-app-notification-design.md)에 iOS 27 알림 트리거의 공식 근거, 추가 공개 예시, 입력 수단 확장 제안과 미확정 사항을 기록했다. 아래 표는 최초 조사 당시의 확보 상태이며, 최신 앱 알림 설계는 후속 문서를 함께 본다.

## 결론과 현재 기준

- 사용자 확인: **실제 문자 자동 수집 성공**(2026-11-08 대화). 기종·OS 버전·잠금 상태·취소 수신까지 확인했다는 의미는 아니다.
- AYR은 현재 **KB국민 체크카드 문자 승인**만 해석한다. 이번 조사에서 앱 지원 수단이나 코드는 변경하지 않았다.
- 전체 대상 15개를 조사했지만, 추가 구현의 근거로 확보한 카드 승인 본문은 **현대카드의 과거 공개 예시 1종**이다. 나머지는 경로·서비스 존재 확인 또는 자료 미확인이며, 최신 템플릿 확보 완료로 간주하지 않는다.
- 은행 계좌 출금 알림, 카드 승인 알림, 페이 결제 알림은 별개다. 연결 은행이나 카드 브랜드만으로 발신 본문을 추정하지 않는다.
- SMS/LMS 본문이 메시지 앱에 도착하는 경로를 우선한다. 앱푸시·알림톡이 있다는 사실만으로 AYR에 본문을 전달할 수 있다고 판정하지 않는다.

### 증거 상태

| 표시 | 뜻 |
| --- | --- |
| 템플릿 확인 | 프로젝트에서 실제 형식을 확인한 본문. 전체 상품·변형을 보장하지 않음 |
| 공개 예시만 확보 | 외부 작성자가 공개한 본문 또는 파서 예시. 실제 수신 증빙·현재 적용 여부는 별도 |
| 자료 미확인 | 신뢰할 본문 예시를 확보하지 못함. 알림 서비스 자체가 없다는 뜻은 아님 |

경로 확인과 템플릿 확인은 별개이며, 실기기 확인은 KB의 사용자 보고 외에는 모두 미실행이다. 금액·개인명·상점·식별 번호·거래 시각은 예시에서 가짜 값으로 치환했다. 원문 스크린샷·개인 거래 데이터·파서 코드는 복제하지 않았다.

## 확보한 비식별 형식과 필터 후보

### T1 — KB국민 체크카드 승인: 프로젝트 확인 형식

근거: [현재 해석기](../Core/Sources/AYRCore/AYRCore.swift)의 `parseKBMessage`, [확정 명세](mvp-spec.md). 외부 표준 템플릿이 아니라 현재 확인한 한 형식이다.

```text
[Web발신]
KB국민체크(0000)
가*명님
11/08 12:34
7,300원
예시상점 사용
```

- 현재 연결 필터: `KB국민체크`. 본문 전체를 전달한다.
- 현재 승인 해석: 해당 접두 줄 + 마지막 줄의 ` 사용` + 금액만 있는 줄 정확히 1개. 이 조건을 다른 카드로 확장하지 않는다.
- 금액 외 잔액·누적액이 추가되는 변형은 별도 확인 대상. KB 취소 템플릿은 여전히 미확인이고 지원하지 않는다.

### T2 — 현대 ZERO 승인: 과거 개발자 공개 예시

근거: 가계부 개발자의 [문자 인식 추가 기록](https://blog.gglab.app/16), **2020-12-06**. 작성자가 게시한 예시이며 현재 금융사의 표준 템플릿이나 AYR 실기기 성공 근거는 아니다.

```text
[Web발신]
현대ZERO승인 가*명
7,300원 일시불
11/08 12:34 예시상점
누적123,400원
```

- 필터 **후보**: `현대ZERO`. 최신 본문과 다른 상품의 브랜드 표기를 확인하기 전 배포용 설정으로 확정하지 않는다. `현대카드`가 본문에 없을 수 있다는 예시다.
- 추출 검토: 일시불 표기 옆 승인액과 `누적` 금액 구분. 전체·부분 취소, 할부, 해외, 승인 거절은 이 예시로 판단할 수 없다.
- 앱의 해당 해석기는 미구현이다. 지금 이 자동화만 만들어도 AYR이 처리할 수 있다는 의미가 아니다.

### B1~B4 — 은행 출금: 승인 대체로 쓰면 안 되는 공개 예시

근거: [Korean Bank SMS JSON Parser](https://gist.github.com/muminoff/5e1aeb5e01097aa421b1dbd8ef06ed03), **2024-11-18**, 공개 코드의 예시 입력. 실제 수신 여부와 최신성은 증명되지 않았다. 아래는 가짜 값으로 치환했고 줄바꿈과 핵심 표식을 유지했다.

| ID | 예시 대상 | 해석 위험 |
| --- | --- | --- |
| B1 | KB 계좌 | `체크카드출금` 형식은 T1과 다른 수집 경로. T1과 함께 합산하면 중복 위험 |
| B2 | 우리 계좌 | 일반 출금만으로 소비·송금·청구대금 구분 불가 |
| B3 | 기업 계좌 | 카드대금 출금을 개별 결제와 함께 합산하는 오류를 검토할 음성 사례 |
| B4 | 농협 계좌 | 금액과 잔액이 한 본문에 공존. 일반 출금은 승인 대체 불가 |

```text
# B1
[Web발신]
[KB]11/08 12:34
000000**000
예시상점
체크카드출금
7,300
잔액123,400

# B2
[Web발신]
우리 11/08 12:34
*000000
출금 7,300원
예시출금처
잔액 123,400원

# B3
[Web발신]
2026/11/08 12:34
출금 7,300원

현대카드
```

**나머지 대상의 필터 문자열은 미확정**이다. 기관명만 넣은 가상의 본문·취소 템플릿·정규식을 만들지 않았다.

## iPhone 자동화 설정안

[Apple 통신 트리거 문서](https://support.apple.com/en-ae/guide/shortcuts/apdd711f9dff/ios)는 메시지의 발신자·포함 문구 조건을 설명하며, 조건을 함께 지정하면 모두 충족해야 한다고 명시한다. 한국어 페이지 조회는 429 오류가 나 영어 검색 색인의 공식 설명을 참고했다. 이 문서가 타사 푸시·알림톡 수신 트리거를 보장하는 것은 아니다. 해당 경로의 본문 접근은 기기에서 확인하기 전까지 **연결 미확인**으로 둔다.

| 수집 경로 | 설정안 | 현재 실행 가능 판정 |
| --- | --- | --- |
| KB 체크 SMS | 메시지 → `KB국민체크` 포함 → 즉시 실행 → `AYR 결제 처리` → 문자 본문에 단축어 입력의 메시지 본문 연결 | 기존 지원. 사용자 자동 수집 성공 보고 |
| 현대 ZERO SMS | T2의 필터 후보를 최신 본문으로 확정한 후 같은 구조 적용 | 앱 해석기·최신 본문 확인 전 실행 대상으로 열지 않음 |
| 기타 카드 SMS/LMS | 실제 본문의 고정 표식 확인 → 해석기 검증 → 수단별 안내 작성 | 필터·본문 미확인, 설정안의 절차만 공통 |
| 앱푸시·카카오 알림톡 | 기기의 트리거·출력 본문·잠금 상태 전달 가능성부터 별도 확인 | 본문을 볼 수 있다는 것과 자동 수집 가능성을 구분. SMS 전환이 가능한지도 확인 |
| 은행 입출금 SMS | 승인 수집 경로로 사용하지 않음 | 일반 출금 소비 합산 미지원 유지 |

공통 원칙:

- 단축어는 **본문 전달만**, 금액·취소 판정은 앱의 `PaymentSource`가 담당한다. 고정 App Intent 1개를 유지한다.
- 자동화는 사용자가 기기에서 설정한다. 이번 산출물은 `.shortcut` 파일·iCloud 공유 링크가 아니다.
- 발신 번호는 출처가 확인되지 않아 고정하지 않았다. 포함 문구만으로 발신 진위가 보장되는 것도 아니다.
- 5만원 이상 무료 문자만 받는 설정은 오늘 총지출의 소액 누락을 만든다. 유료 신청을 대신 실행하지 않으며 온보딩에서 조건을 안내해야 한다.
- [카카오 카드영수증 안내](https://bzm-moa.kakao.com/receipt/setting/guide)는 SMS·앱푸시를 알림톡이 대체할 수 있음을 명시한다. 단축어가 끊기면 알림 경로 변경 여부를 먼저 확인한다. 카드영수증은 카카오페이 결제 알림과 별개다.

### 페이와 연결 카드의 중복 수집

이는 구현된 중복 제거 기능이 아니라 **경로 선택 제안**이다.

| 결제 방식 | 권장 경로 후보 | 제외해야 할 두 번째 합산 |
| --- | --- | --- |
| 카카오페이·네이버페이에 등록한 카드 결제 | 형식·수신이 확인된 연결 카드 승인 SMS 우선 | 같은 결제의 페이 알림·계좌 출금 |
| 페이머니·포인트 결제 | 최종 결제 알림의 접근·금액 의미가 확인돼야 지원 가능 | 충전액·자동충전 계좌 출금·적립액 |
| 포인트+카드/머니 복합 결제 | 알림별 금액이 총액인지 실제 차감액인지 확인 전 지원 판정 보류 | 총결제액과 카드 차감액을 각각 합산 |
| 신용카드 대금 납부 | 소비로 신규 합산하지 않음 | 앞서 합산한 개별 카드 승인과 중복 |

결제마다 ID를 얻을 수 있는지도 미확인이다. 금액·시각이 비슷하다는 이유로 서로 다른 결제를 제거하는 정책은 도입하지 않는다.

## 취소·오인 방지 검토와 후속 구현의 통과 조건

아래는 이번에 실행한 테스트 결과가 아니라, 형식을 확보한 수단을 실제 지원하기 전 필요한 검증 기준이다.

| 상황 | 검토 기준 | 현재 근거 상태 |
| --- | --- | --- |
| 승인 금액 + 누적액/잔액 | 승인액만 선택, 모호하면 거부 | T2, B1~B4로 위험 확인 |
| 전체·부분 취소 | 취소액·원승인액 구별, 전날 취소·같은 금액 여러 건 검토 | 일부 공식 서비스에 취소 포함은 확인했지만 **취소 본문 확보 0종** |
| 충전·자동충전·송금·인출 | 승인 표식을 만족하지 않으면 소비에 넣지 않음 | 기관별 본문 미확인. 보편적인 단어 목록만으로 지원 선언 금지 |
| 결제 요청·본인 인증·승인 거절 | 실제 승인과 구분, 소비에 넣지 않음 | 신한 약관 등 서비스 종류 확인, 본문 미확인 |
| 카드론·현금서비스·결제예정액·대금 입금 | 소비 승인과 구분 | 신한·삼성·롯데 공식 설명에서 혼재 확인 |
| 해외·할부·후불교통·복합 결제 | 통화·승인액 의미·발송 시점 별도 확인 | 이번 본문으로 미검증, 임의 환산/분할 금지 |
| 지연·중복·채널 전환 | 수신 누락/이중 집계·날짜 오인 확인 | 서비스 설명에 지연 가능성. 현재 AYR은 수신일의 현지 날짜로 집계 |
| 공백·줄바꿈·RCS/채팅+ 변형 | iPhone의 실제 전달 본문으로 확인 | [CardSMS 개발자 변경 기록](https://cardsms-cc51a.web.app/version.html)에 채팅+별 인식 대응 존재. Android 대응은 iOS 성공 근거가 아님 |

확장 순서 제안은 **현대 ZERO의 최신 승인 형식 확인 → 형식이 확보되는 다른 카드 SMS → 별도 수집 가능한 페이 경로**다. 승인 성공을 취소 성공으로 확대하지 않는다. 지원 추가 시 비식별 회귀 입력으로 승인/거절/금액 선택을 검증한 뒤, 평소 결제에서 잠금 상태 수신·오늘 합계·위젯/Live Activity 갱신을 확인한다. 실제 거래를 새로 만들 필요는 없다.
