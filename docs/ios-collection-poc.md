# iPhone 토스 알림 수집 POC

> 현재 [개인용 iOS 네이티브 앱](mvp-spec.md)의 수집 전제를 확인하는 절차입니다. 실행 단위 5 전에 2~4장을 실기기에서 확인합니다. 본문의 Flutter 언급은 이전 계획이며 현재는 Swift 네이티브 앱입니다.

목적: 앱을 만들기 전에 **토스의 실제 알림이 단축어에 전달되고, 승인·취소와 금액을 구분할 수 있는지** 확인합니다.

현재 상태는 **실기기 실행 전**입니다. 아래 절차는 가져오기 가능한 `.shortcut` 파일이 아니라, iPhone에서 사용자가 구성할 실행 가이드입니다. 앱 설치만으로 자동화가 활성화되는 방식으로 가정하지 않습니다.

## 1. 준비

- iOS 27 이상 iPhone에서 단축어와 토스 앱을 준비합니다.
- 토스의 대상 거래 알림과 iOS의 토스 알림을 허용합니다.
- 정확한 iOS 버전과 토스 앱 버전만 결과표에 기록합니다. 계정·전화번호·카드번호는 기록하지 않습니다.
- 초기 검증은 잠금을 해제한 상태에서 합니다. 잠금 상태 검증은 별도 수행합니다.
- 금융사 계약·유료 서비스·실제 결제·취소를 이 가이드가 대신 실행하지 않습니다.

## 2. 수신 확인 자동화 만들기

OS 언어와 세부 버전에 따라 메뉴 이름이 다를 수 있습니다. 아래는 액션의 역할을 기준으로 한 구성입니다.

1. **단축어**에서 새 단축어를 만들고 이름을 `AYR 토스 수신 확인`으로 지정합니다.
2. 자동화 추가에서 **알림(Notification)**을 선택하고, 대상 앱을 **토스**로 지정합니다. 처음에는 제목·메시지 필터를 추가하지 않습니다.
3. 다음 작업에서 텍스트 액션을 추가하고, 고정 문자열이 아니라 **알림 트리거의 출력 변수**를 연결합니다.
4. 출력 변수에서 제공되는 속성을 확인합니다. 제목(Title), 부제(Subtitle), 메시지(Message/Content)와 앱 정보가 있는지 확인합니다. 정확한 속성명이나 제공 여부가 다르면 결과표에 남깁니다.
5. 각 텍스트 속성에 **개수 세기(Count)의 문자 수**를 적용합니다. 아래처럼 수신 여부와 길이만 조합합니다. 실제 본문은 포함하지 않습니다.

   ```text
   AYR 수신 확인
   제목: [제목 문자 수]자
   부제: [부제 문자 수]자
   메시지: [메시지 문자 수]자
   ```

6. 위 텍스트를 **알림 보기(Show Notification)** 액션으로 표시합니다. 단축어의 알림 권한을 허용합니다. 이 알림은 단축어 앱에서 발신하므로 토스만 지정한 트리거를 다시 실행해서는 안 됩니다.
7. 자동화를 활성화하고 확인 없이 실행하는 옵션이 있으면 선택합니다. 잠금 상태 실행 허용 옵션이 있으면 잠금 검증 전에 활성화합니다.
8. 자동화를 저장합니다. 편집기의 수동 실행은 구성 확인일 뿐 실제 알림 수신 검증으로 기록하지 않습니다.

알림 트리거가 없거나 출력 속성을 선택할 수 없으면 여기서 중단하고, 메뉴가 없는 단계만 보고합니다. 입력을 수동 텍스트로 바꾸어 실제 연동으로 처리하지 않습니다.

## 3. 실제 발신 알림 검증

### 토스페이 온라인 결제

1. [토스페이먼츠 개발자센터](https://developers.tosspayments.com/)의 개발 연동 체험 상점·테스트 키를 이용한 **공식 테스트 환경**을 사용합니다. [테스트 환경 안내](https://docs.tosspayments.com/guides/v2/get-started/environment)를 먼저 확인합니다.
2. 이용 가능한 결제창 예제/샌드박스에서 토스페이를 선택하고 본인의 iPhone으로 인증합니다. 이 문서는 테스트 결제창 자체를 구현하거나 계정을 생성하지 않습니다. 테스트 환경을 이용할 수 없으면 해당 항목을 미실행으로 남깁니다.
3. 요청·인증 단계의 토스 알림과 승인 완료 후 알림을 각각 확인합니다. 인증에 성공했다는 화면만으로 결제 승인 알림이 왔다고 기록하지 않습니다.
4. 테스트 취소를 제공하는 경우에만 취소 알림도 확인합니다. 테스트 승인·취소 알림이 없으면 `알림 없음`으로 기록합니다. 실제 거래도 알림이 없다고 단정하지 않습니다.

테스트 키·계정 정보는 저장소나 채팅에 넣지 않습니다. 토스페이 직연동 상점 키와 토스페이먼츠 체험 상점 키를 같은 키로 가정하지 않습니다.

### 토스뱅크 체크카드

1. 사용자가 직접 하는 평소 결제에서 토스 알림과 `AYR 수신 확인` 알림을 비교합니다.
2. 실제로 취소할 사유가 있는 거래의 취소 알림을 별도로 확인합니다. 이 가이드만을 위해 결제·환불을 자동 수행하지 않습니다.
3. 토스페이 테스트 결제의 결과를 체크카드 실거래 검증으로 복사하지 않습니다.

## 4. 내용 확인과 금액 추출

**먼저 수신 여부를 통과한 뒤** 잠금 해제 상태에서만 다음을 진행합니다.

1. 진단 단축어를 복제해 `AYR 토스 내용 확인`으로 이름을 지정합니다. 중복 실행을 피하도록 기존 진단 자동화는 끕니다.
2. 트리거 출력의 제목·부제·메시지를 연결한 텍스트를 **결과 보기(Show Result)**로 기기에서만 확인합니다. 이 단계는 사용자 확인용으로 화면을 열거나 잠금 해제를 요구할 수 있습니다. 백그라운드 실행 검증에는 이 액션을 사용하지 않습니다.
3. 본문에 승인 금액과 승인/취소 여부가 있는지 확인합니다. 결과표에는 내용 자체 대신 `금액 있음/없음`, `종류 구분 가능/불가`만 적습니다.
4. 완료를 뜻하는 표현, 금액 위치, 날짜·거래 식별 필드가 실제로 확인된 형식에 한해서 필터와 **텍스트 일치(Match Text)** 규칙을 구성합니다. 승인·취소·부분 취소는 각각 확인합니다. 아직 실제 형식이 없으므로 이 저장소는 토스 전용 정규식을 임의로 제공하지 않습니다.
5. 금액이 여러 개(잔액·누적액·캐시백 등)일 때 첫 숫자를 무조건 사용하지 않습니다. 승인 금액 위치를 확정할 수 없다면 실패로 기록합니다.
6. 잠금 검증으로 돌아가기 전에 원문 표시 액션을 제거하고 문자 수만 표시하는 수신 확인 구성으로 되돌립니다. 원문을 파일·메모·클립보드·iCloud·웹 요청에 저장하거나 전달하지 않습니다.

### 실제 형식을 확인한 뒤의 반복 검증

별도 자동화 없는 테스트 단축어에서 **텍스트 → 확인한 필터/추출 규칙 → 결과 보기**를 실행합니다. 원문 대신 같은 구조의 가짜 이름·가짜 금액을 사용합니다.

| 테스트 입력 | 기대 결과 |
| --- | --- |
| 확인된 승인 형식, 가짜 8,500원 | 승인 금액 8,500원 |
| 같은 형식, 가짜 12,000원 | 승인 금액 12,000원 |
| 확인된 취소 형식 | 승인으로 합산하지 않고 취소로 구분 |
| 결제 요청·인증·광고 | 승인으로 구분하지 않음 |
| 잔액·캐시백 금액이 함께 있는 형식 | 확인된 승인 금액만 추출, 불명확하면 거부 |
| 빈 본문·알 수 없는 형식·외화만 있음 | 원화 지출로 임의 변환하지 않음 |

이 테스트는 추출 규칙 검증입니다. 토스 발신 자동화 실행이나 중복 제거·취소 대조 로직을 검증한 것으로 보고하지 않습니다.

## 5. 잠금·연속 알림·실패 확인

- 원문을 표시하지 않는 수신 확인 자동화로, 잠금 상태에서도 실행되는지 확인합니다.
- 연속 알림에서 토스 알림 수와 진단 알림 수가 맞는지 비교합니다. 놓친 것이 있으면 누락 가능성을 기록합니다.
- 자동화를 끈 동안 알림이 집계되지 않는지, 다시 켠 뒤 새 알림을 받는지 확인합니다. 지난 알림이 복구된다고 가정하지 않습니다.
- 자동화 실행과 토스 알림을 각각 확인합니다. 단축어의 알림 권한 거부로 진단 알림만 안 보이는 경우와 트리거 미실행을 구분합니다.

## 6. 결과와 다음 단계

[결과표](poc-results.md)를 채웁니다. 알림 원문·실제 금액·상점명·거래 식별자는 공유하지 않습니다.

두 결제 유형에서 실제 발신 알림 수신, 승인 금액 추출, 취소 구분이 확인되어야 수집 POC를 성공으로 판단합니다. 모의 입력 통과만으로 성공 처리하지 않습니다.

본문 미전달·승인 금액 불명확·취소 구분 불가가 있으면 Flutter 앱 구현 전에 실패 조건을 보고하고 수집 경로를 재결정합니다. 앱 구현으로 넘어가면 중복 식별·원거래 취소 연결·날짜·저장·표시 검증을 추가합니다.
