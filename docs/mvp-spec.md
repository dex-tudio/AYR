# MVP 확정 명세

상태: 개인용 iOS 네이티브 앱으로 전환 확정(2026-11-03). 토스 알림의 단축어 전달과 실제 알림 형식은 실기기 검증 전입니다.

## 목표와 범위

- 본인 iPhone 한 대에서 토스 결제 알림을 수동 입력 없이 반영해 오늘 합계와 신분별 문구를 보여줍니다.
- 수집: 토스 알림 → 단축어 자동화(알림 본문을 앱에 전달만) → AYR 앱 App Intent. iOS는 앱이 다른 앱의 알림을 읽지 못하므로 자동화 1개는 직접 만듭니다.
- 계산·저장: 앱이 기기 안(App Group)에 저장합니다. 서버·계정·외부 전송은 없습니다.
- 표시: 잠금화면 위젯과 Live Activity, 앱 화면.
- 대상: 토스페이 온라인 결제, 토스뱅크 체크카드 알림. 다른 금융사·Android·배포는 범위 밖입니다.
- 빌드: Mac 없이 GitHub Actions macOS 러너 → TestFlight 설치. 최소 iOS 17.
- 이전 PWA·서버·금융 API·앱인토스 조사는 [금융 API 검토 기록](financial-api-review.md)에 보관합니다.

## 금액과 문구

최초 실행 시 신분을 선택합니다. 신분 변경 시 금액은 유지하고 문구만 다시 계산합니다.

| 신분 | 하루 기준 금액 |
| --- | ---: |
| 학생 | 20,000원 |
| 취준생 | 30,000원 |
| 직장인 | 50,000원 |

| 오늘 합계 / 하루 기준 금액 | 표시 문구 |
| --- | --- |
| 50% 미만 | 아직 여유 있어요 |
| 50% 이상, 100% 미만 | 슬슬 조절해볼까요? |
| 100% 이상 | 님 부자임? |

금액은 원 단위 정수입니다. 표시 예: `오늘 12,000원 · 슬슬 조절해볼까요?`(학생).

## 집계 규칙

| 상황 | 동작 |
| --- | --- |
| 승인 알림 | 승인 금액을 오늘 합계에 더합니다. 결제 요청·인증·광고·송금·충전 알림은 제외합니다. |
| 날짜 변경 | 기기 현지 시간대의 날짜(`yyyy-MM-dd`)가 바뀌면 다음 알림·앱 실행·위젯 갱신 때 0원부터 다시 집계합니다. 자정 정각 갱신은 보장하지 않습니다. |
| 취소 알림 | 오늘 승인 중 같은 금액이 있으면 그 승인 1건을 뺍니다. 없으면(전날 결제 취소, 부분 취소) 차감하지 않고 무시합니다. 알림에는 원거래 정보가 없어 생긴 한계입니다. |
| 같은 금액의 별도 결제 | 각각 반영합니다. |
| 같은 알림 중복 수신 | 알림에 거래 ID가 없어 구분하지 못하고 두 번 합산될 수 있습니다. |
| 금액·종류 해석 실패 | 합산하지 않습니다. |
| 0원 이하 금액 | 거부합니다. |
| 외화 | 원화 금액이 없으면 합산하지 않습니다. |

토스 알림 해석 규칙(승인·취소 키워드, 금액 위치)은 실제 알림 형식을 확인한 뒤 정합니다.

## 개인정보

- 알림 원문은 저장하지 않고 승인 금액만 저장합니다. 당일 기록만 유지합니다.
- 알림 원문·금액·상점명을 로그·Git·채팅에 남기지 않습니다.

## 실행 단위

| # | 단위 | 검증 |
| --- | --- | --- |
| 1 | 핵심 로직 Swift 패키지(`Core/`): 합산·취소·날짜 초기화·신분별 문구 | `swift test` (Docker·CI) |

| 4 | Live Activity | 실기기 잠금화면 상시 표시 |
| 5 | 토스 알림 연결 + 해석 규칙 | 실제 결제 알림 (확인용 단축어 결과 필요) |
